# Homem on Mac

Build the standalone macOS app with the `HomemMac` scheme in Xcode, or run `bash scripts/build-mac.sh`. It requires macOS 14 or later. The native SwiftUI/AppKit shell shares API clients, accounts, chat models, workspace state, desktop transport, and resource schemas with iOS and visionOS.

The main window uses a native navigation sidebar and compact unified toolbar. Open chat, files, terminal, and desktop panes side by side or stacked. The **Workspace** menu opens independent tool windows; they can be moved to other displays using macOS window controls. Each detached window retains the account and workspace that opened it. File editing uses native text views and open/save panels. Terminal input and remote desktop rendering use AppKit views.

Keyboard shortcuts: **⌘⇧N** starts a conversation; **⌘⇧C/F/T/D** opens a chat/files/terminal/desktop window; **⌘Return** sends from the focused composer. **⌘,** opens account settings. The Library and Agents screens provide server-backed management with the same OpenAPI schemas as the other platforms.

## Sign-in and Keychain

The Mac App Store app uses bundle ID `ad.neko.homem`. All three platforms use the `7P8CLHDH5G.ad.neko.homem` Keychain access group. Saved credentials, official sessions, and the account directory are synchronizable Keychain items. Native macOS explicitly uses the data protection Keychain. When iCloud Keychain is enabled under the same Apple Account, another device can restore a synced account without entering its credentials again. Accounts are checked when windows become active and every 30 seconds. Expired server tokens or cookies can still require sign-in again.

Existing local credentials are copied to the synchronizable Keychain before the original is removed. Drafts remain local. Removing an account removes its synchronized credential and listing. Native signed tests verify saving, updating, migration, deletion, window restoration, and account isolation. Physical iCloud propagation between devices still needs device testing.

## Signing and release

The checked-in project uses automatic signing for team `7P8CLHDH5G`; configure the team in Xcode for local development. The native app is sandboxed and permits server connections, incoming WebRTC traffic, microphone recording, and user-selected files. It does not embed the iOS share extension.

The binary is built for `MACOS`, with deployment target 14.0, using `HomemMac/Info.plist` and native Mac icons. Source `project.yml` is generated by XcodeGen; commit the generated project and shared scheme when changing it.

Native UI captures and verification are in [the Mac UI report](ui/2026-10-03-native/README.md). App Store upload images are in `docs/app-store/screenshots/native-mac/en-US/`.
